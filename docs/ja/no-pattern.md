# パターンにない画面を作るとき

このガイドでは、同じ種類の本体の画面があれば、それに倣います。これは絶対の決まりではなく方針です。合う画面がないときは、足りないものを足し、その理由を残します。

<a id="look-for-the-closest-core-screen-first"></a>

## まず近い本体の画面を探す

たいていの画面は、このガイドのパターンの組み合わせです。タイトルとアクション、セクション、一覧、設定、フォーム、メッセージのどれかです。新しく見える画面も、中身が違うだけのことがほとんどです。いちばん近い本体の画面から始めて、中身だけを変えます。

<a id="add-only-what-is-missing"></a>

## 足りないものだけを足す

合うパターンがないときは、用が足りる最小限のものを足します。

| 足すもの | 足し方 |
| --- | --- |
| クラス | 本体のクラスの隣に、その要素が何かを表す名前で付けます。テーマから整えられるようになります。本体も、`table.list` に `enumerations` を付けています。 |
| CSS | プラグインの要素だけに限って、少しだけ足します。本体の CSS 変数(`application.css` の `--oc-gray-4` など)を使うと、テーマや暗い配色にも合います。 |

足した理由は、コミットのメッセージかプラグインの資料に書きます。

<a id="keep-cores-elements-as-they-are"></a>

## 本体の要素は変えない

1 つの画面のために、本体の要素(`.box`、`table.list`、`.tabular`、見出し)の見た目を変えません。標準のスタイルが合わないときは、たいてい、マークアップがまだ本体のパターンになっていません。直すのはマークアップのほうです。

<a id="compare-with-the-core-screen"></a>

## 本体の画面と比べる

作った画面と、手本にした本体の画面を、同じ幅で英語と日本語のスクリーンショットに撮って比べます。セクションのあいだの間隔も見ます。
