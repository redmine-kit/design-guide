# 本体にパターンがないとき

このガイドの方針は、同じ種類の本体の画面があれば、それに倣うことです。絶対の決まりではなく、方針です。

- **まず、いちばん近い本体の画面を探します。** たいていの画面は、ここにあるパターンの組み合わせです。タイトルとアクション、セクション、一覧、設定、フォーム、メッセージです。新しく見える画面も、たいていは中身の違うそのどれかです。
- **合うものがないときは、** 足りないものを、理由をもって足します。
  - 本体のクラスの隣にクラスを足します。名前は、それが何かを表すものにします(たとえば、本体が `enumerations` でしているように、`table.list` に種類のクラスを付けます)。テーマがそのクラスで整えられます。
  - プラグインの要素だけに限った少しの CSS を足します。本体の CSS 変数(`application.css` の `--oc-gray-4` など)を使えば、テーマや暗い配色にも合います。
  - 理由を、コミットのメッセージかプラグインの資料に書きます。
- **1 つの画面のために本体の要素を整え直しません**(`.box`、`table.list`、`.tabular`、見出し)。標準のスタイルが合わないときは、たいてい、マークアップがまだ本体のパターンになっていません。
- **倣った本体の画面と結果を比べます。** 同じ幅のスクリーンショットを英語と日本語で比べ、セクションのあいだの間隔も見ます。
- **新しい種類の画面が必要になったら、** そのパターンをここに足します。
